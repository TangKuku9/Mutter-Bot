# 服务商连接与模型目录

AI 设置的“管理服务商”维护可重复使用的连接。可以从内置模板添加，也可以添加自定义连接；同一家服务商的多个账号、地址和区域可以分别命名保存。

内置目录包括中国与国际服务商，按分组搜索选择，并显示目录核查日期及官方文档入口，详见[内置服务商与模型目录](ai-provider-catalog.md)。已有连接可点击“补充最新内置模型”后保存；此操作保留原有模型、默认选择、密钥和预设引用。

每条连接包含接口协议、根地址、可选 API Key、模型目录、默认模型、请求头和超时。当前支持 OpenAI 兼容 Chat Completions 与 Gemini 原生 generateContent。获取模型列表只读取目录，手动添加的模型和显示名称在获取后仍会保留；“测试当前模型”使用正式调用适配器发起一次短请求。

日常设置与预设编辑使用相同的服务商/模型选择器，支持搜索、模型收藏与最近使用。收藏和最近记录保存在当前浏览器，并按连接区分；连接、模型和预设保存在服务端数据库。

新预设保存连接 ID、模型 ID 与行为参数。密钥由连接统一管理；更新连接密钥后，引用它的预设会使用更新后的值。需要独立配置时可以复制连接。正在使用或被预设引用的连接不能删除，正在被引用的模型不能移除。

旧配置在启动时幂等迁移：当前配置成为“现有连接”，含独立密钥的预设绑定对应连接；相同地址但不同密钥保持为独立连接。无法判断归属的无密钥旧预设显示“未绑定连接”（引用已消失连接的显示“连接已不存在”），在预设库的“编辑预设”中选择服务商和模型即可。旧版本 API 的原始配置字段继续保留兼容；解绑连接时会清空主配置里的密钥副本。迁移只在启动时执行一次，升级前建议备份 SQLite（含 `-wal`/`-shm`）；指向已消失连接的悬空引用会被清理并按旧字段重建。

连接的地址、协议、认证或请求头发生变化时，相关联网探测结果失效；仅修改显示名称不会改变连接引用。主表单选择连接后，需要“保存配置”生效；“保存连接”只维护连接库，“应用并保存”则立即应用整份预设。连接版本变化（地址、密钥、协议、模板、请求头、超时）会让引用它的预设与主配置的联网搜索策略失效，需要重新检测；版本为空一律按过期处理。

## 边界与安全

| 项目 | 上限 / 规则 |
|---|---|
| 连接数量 | 100 条（并发创建也在同一写锁内计数） |
| 连接名称 | 1–64 字符 |
| 接口地址 | HTTP(S)、≤2048 字符，不允许查询参数、锚点或 userinfo |
| 超时 | 5–120 秒；连接上的显式值会覆盖默认单次尝试上限，但仍受全局期限约束 |
| API Key | ≤8192 字符，不允许控制字符；打码值表示“未修改” |
| 自定义请求头 | ≤20 个，名称仅限字母/数字/`-`/`_`，值 ≤8192 字符；`host`、`content-length`、`transfer-encoding`、`connection`、`content-type` 为受保护字段 |
| 模型目录 | 1–2000 个；ID ≤256 字符，不允许控制字符，大小写敏感去重 |
| 模型限额 | 上下文 4096–1048576 tokens，输出 64–32768 tokens（仅登记已知信息） |
| 上游调试 | “获取模型列表/测试当前模型”合计每分钟 60 次、并发 2 个 |

安全约定：

- 打码值只会在**与原地址同 origin**（scheme + host + port）时解析为已保存的密钥；更换地址后必须重新填写 Key 与请求头，否则会拒绝保存、测试和获取模型。独立搜索的 Key 与未绑定连接的旧版主配置遵循同一条规则：改了地址却仍提交打码值会被拒绝，Key 不会跟随新地址。
- 校验会拒绝链路本地地址（`169.254.0.0/16`、IPv6 link-local）、云元数据主机与 IPv6 元数据地址（`fd00:ec2::254`、`fd20:ce::254`）；回环与内网地址仍然允许，供本地推理服务使用。
- 保存校验之外，所有出站请求（AI 连接、外搜服务商、图片下载、更新清单）都在**建立 TCP 连接前**重新解析域名并校验解析结果，因此把域名在保存后改指 `169.254.169.254` 的 DNS rebinding 也无法绕过。系统若配置了 HTTP 代理，校验收到的会是代理地址，目标域名由代理解析——此时安全边界由代理承担。
- AI 模型上游请求不跟随 HTTP 重定向；外搜、图片与更新下载允许重定向，但每一跳都会重新执行建连地址校验。
- 上游失败只回显粗类原因（鉴权、地址/模型不存在、限流、上游不可用），不逐字回显状态码，避免把调试端点变成内网探测工具。
- 同名自定义请求头会覆盖内置 `Authorization` / `x-goog-api-key`，用于网关鉴权；这是刻意保留的能力，配置时请确认没有误覆盖。
- 请求参数兼容规则先按**连接模板**判定；OpenRouter、Together、SiliconFlow、Groq 这些聚合平台再按模型 ID 的厂商前缀（`openai/`、`moonshotai/`、`MiniMaxAI/`，无前缀时按模型名）推断家族，套用与官方端点相同的约束。识别不出厂商时保持模板本身的行为，不猜。Claude 的 `json_object` 规避只针对 Anthropic 官方兼容层，聚合平台自己会翻译该字段，因此不在聚合连接上套用。
- 主配置行会保留一份与连接一致的兼容字段（含密钥副本）供旧版 API 使用；解绑连接时该副本会被清空。

## 验证

```powershell
dotnet build Mutter.sln
dotnet run --project tools/ProactiveCheck -- --logic-only
dotnet run --project tools/ProactiveCheck -- --connections-only
cd web
npm test
npm run build
npm run test:ui
```

`--connections-only` 使用合成临时数据库和 HTTP 响应，覆盖旧库补表/补列、迁移幂等、密钥隔离与打码往返、origin 变更拒绝、版本失效、预设/当前配置的模型引用保护、两种协议的模型获取与实际传输、Gemini 结构化输出与数量上限，不调用真实模型账号。

浏览器验收入口为“AI 设置 → 管理服务商”。启动 Web 宿主：

```powershell
dotnet run --project src/Mutter.Web --launch-profile http
```

默认访问 `http://127.0.0.1:5188/#/ai-settings`，使用原有面板账号登录。
