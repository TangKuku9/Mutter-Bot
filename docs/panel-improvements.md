# 性能与管理面板改进

本轮基于 `acfabca` 的 AI 运行时改动继续实现，分支为 `codex/performance-panel-experience`。

## 1. 用量账本与统计口径

`AiCallRecords` 每次实际 HTTP 请求记录一行，包括正式回复、主动判断、格式修复、搜索和管理员手动探测。记录请求人、群、用途、模型、耗时、状态与上游返回的输入/输出用量；不保存密钥、请求提示词或原始模型响应。

用户排行按发起请求的用户 ID 聚合，主动评估与管理员探测不归给群里的某个成员。回复与发送记录通过 `AiOperationId` 关联调用，避免成功回复再计一次用量。网络失败或上游缺少 usage 时保留未知，不推算费用。

升级前只有回复级用量，继续计入已知 Token，但单列为历史回复数，不伪造实际请求数，也不猜测用户归属。图表、首页统计和用户排行均说明此口径。若数据库暂时不可写，记账错误写入本地日志，不改变上游请求结果；统计仅反映成功保存的记录。

## 2. 数据库汇总与短期缓存

按日、群和用户的 SUM/COUNT/GROUP BY 在 SQLite 内执行，不读取聊天正文与原始消息段。统一用量接口 `/api/chat/usage` 一次返回图表、排行与摘要。只缓存聚合结果，10 秒过期；并发命中同一结果不会重复执行汇总。首页总数也有 10 秒缓存。

日期按北京时间自然日计算。读取聊天记录关闭 EF 跟踪，分页按时间与 ID 稳定排序，群配置列表使用字典匹配。新增时间与操作关联索引。

## 3. 图片内存与下载

图片缓存同时限制 64 项与约 64 MiB 计入缓存的占用，按最近访问淘汰，正常图片 2 分钟过期，失败结果只保留 5 秒。定时清理可释放闲置过期项；大型 data URI 用摘要作缓存键，不长期保留整份编码文本。

并行下载最多 4 张，下载及等待下载槽位共用 10 秒截止时间。同一图片合并下载，取消一个等待者不会取消其他等待者的共享下载。多图准备保持原顺序与原有整请求字节预算。data URI 解码后也执行单张 8 MiB 检查。缓存限制不是整个进程内存上限，处理中的图片、编码请求与其他服务仍有临时内存开销。

## 4. 实时与筛选

面板共用一条 SignalR 连接，支持初次连接失败重试与断线恢复。切换页面仅退订页面事件；日志重复订阅先清理旧订阅，重连缓冲按日志标识去重，界面批量更新。

聊天记录、主动日志和统计只允许最后一次查询写回，离开页面取消等待。实时消息按当前筛选条件刷新，不直接增加不匹配的总数；查看旧页时显示新消息提醒，主动返回最新。后台标签暂停状态轮询，前一轮查询完成后再安排下一轮，首页与关于页共用机器人状态。

## 5. 配置编辑

AI 设置显示输入、输出、安全余量的容量分配，保存前检查三个数是否兼容。AI 设置、主动设置与群编辑有未保存修改提醒；刷新 AI 设置也会先确认。

群设置 API 的 `updateMemory=true` 可同时提交摘要、群名与群设置，由一次 SaveChanges 事务保存。旧客户端或摘要读取失败时不提交此标记，保留已有摘要；清空记忆仍是单独、需确认的即时操作。

## 6. 运行过程

首页展示队列等待/执行数、容量、繁忙拒绝与过期计数、图片缓存用量，以及最近 100 次模型请求中成功请求的平均/P95 耗时。该模型耗时不含排队、图片准备或发送；失败数也明确使用同一近期样本。

当前任务与本次启动最近 100 条任务保存在内存，每条最多 32 个步骤；模型请求与发送回执持久化。`/api/runtime/operations/{id}` 可关联查看上下文准备、图片、模型调用和发送结果。重启后近期任务步骤消失，已保存的调用与发送记录仍可查看。首页展示最近 20 次模型请求和前 30 条任务，不自动重发不确定结果。

普通回复遇到模型执行超时，会在宿主仍运行时使用独立有限的发送期限给出超时提示；停机取消不额外发送。

## 7. 共用群记忆

普通 @ 回复新增 `AiConfigs.GroupMemoryInjectionEnabled` 全局开关，默认开启；主动发言保留自己的全局开关。两者都尊重群级禁止注入设置，私聊不读取群记忆。主动工作流只注入一次，普通回复的记忆纳入最终输入预算。摘要仍由管理员维护，不自动生成或更新。

## 8. 前端按需加载

Element Plus 改为组件及样式按需引入，路由继续懒加载；服务式消息框样式显式引入，中文语言配置通过 ConfigProvider 提供。构建插件选择支持项目现有 Node 版本线的 28.x。

同一构建模式下，入口主 JavaScript 从约 1,121,703 字节降为约 383,950 字节，减少约 66%。这是入口文件未做传输压缩时的大小，不代表整个首页的所有资源，也不等同于实际加载耗时的降幅。统计图表仍只在进入统计页时加载。

## 兼容与验证

数据库只通过现有幂等升级增加调用表、关联列、记忆开关和索引，不删除旧数据。回退程序时保留这些附加结构。

```powershell
dotnet build Mutter.sln
dotnet run --project tools/ProactiveCheck -- --logic-only
cd web
npm test
npm run build
```

运行时回归共 19 组，新增覆盖实际请求归属、未知用量、格式重试、手动探测、5000 条带长正文的记录汇总、缓存命中、图片并发/淘汰/取消、独立记忆开关、保存事务回滚和过程关联。前端逻辑测试覆盖旧请求晚到、页面取消、过滤条件及容量关系，已接入 CI。

本地另用 Edge 无界面浏览器与合成 API/SignalR 数据检查全部管理页面、编辑提醒、合并保存、实时筛选、断线恢复、日志去重、组件解析与首页布局。验证不读取部署数据库，不访问真实 QQ 或付费模型。
