# 性能与管理面板改进

本轮基于 `acfabca` 的 AI 运行时改动继续实现；聊天时间线、分群择机参数与 AI 设置分区在 `codex/ai-settings-panels` 分支补齐。

## 1. 用量账本与统计口径

`AiCallRecords` 每次实际 HTTP 请求记录一行，包括正式回复、主动判断、格式修复、搜索和管理员手动探测。记录请求人、群、用途、模型、耗时、状态与上游返回的输入/输出用量；不保存密钥、请求提示词或原始模型响应。

用户排行按发起请求的用户 ID 聚合，主动评估与管理员探测不归给群里的某个成员。回复与发送记录通过 `AiOperationId` 关联调用，避免成功回复再计一次用量。网络失败或上游缺少 usage 时保留未知，不推算费用。

升级前只有回复级用量，继续计入已知 Token，但单列为历史回复数，不伪造实际请求数，也不猜测用户归属。图表、首页统计和用户排行均说明此口径。若数据库暂时不可写，记账错误写入本地日志，不改变上游请求结果；统计仅反映成功保存的记录。

## 2. 数据库汇总与短期缓存

按日、群和用户的 SUM/COUNT/GROUP BY 在 SQLite 内执行，不读取聊天正文与原始消息段。统一用量接口 `/api/chat/usage` 一次返回图表、排行与摘要。只缓存聚合结果，10 秒过期；并发命中同一结果不会重复执行汇总。首页总数也有 10 秒缓存。

日期按北京时间自然日计算。读取聊天记录关闭 EF 跟踪，分页按时间与 ID 稳定排序，群配置列表使用字典匹配。新增时间、操作关联、主动消息时间与旧版模型用量索引；旧库升级时只补索引，不重写历史行。

## 3. 图片内存与下载

图片缓存同时限制 64 项与约 64 MiB 计入缓存的占用，按最近访问淘汰，正常图片 2 分钟过期，失败结果只保留 5 秒。定时清理可释放闲置过期项；大型 data URI 用摘要作缓存键，不长期保留整份编码文本。

并行下载最多 4 张，下载及等待下载槽位共用 10 秒截止时间。同一图片合并下载，取消一个等待者不会取消其他等待者的共享下载。多图准备保持原顺序与原有整请求字节预算。data URI 解码后也执行单张 8 MiB 检查。缓存限制不是整个进程内存上限，处理中的图片、编码请求与其他服务仍有临时内存开销。

## 4. 实时与筛选

面板共用一条 SignalR 连接，支持初次连接失败重试与断线恢复。切换页面仅退订页面事件；日志重复订阅先清理旧订阅，重连缓冲按日志标识去重，界面批量更新。

聊天记录、主动日志和统计只允许最后一次查询写回，离开页面取消等待。实时消息按当前筛选条件刷新，不直接增加不匹配的总数；查看旧页时显示新消息提醒，主动返回最新。后台标签暂停状态轮询，前一轮查询完成后再安排下一轮，首页与关于页共用机器人状态。

## 5. 配置编辑

AI 设置显示输入、输出、安全余量的容量分配，保存前检查三个数是否兼容。AI 设置、主动设置与群编辑有未保存修改提醒；刷新 AI 设置也会先确认。

群设置 API 的 `updateMemory=true` 可同时提交摘要、群名与群设置，由一次 SaveChanges 事务保存。旧客户端或摘要读取失败时不提交此标记，保留已有摘要；清空记忆仍是单独、需确认的即时操作。

## 6. 运行过程

首页展示队列等待/执行数、容量、繁忙拒绝与过期计数、图片缓存用量，以及最近 100 次模型请求中成功请求的平均/P95 耗时。该模型耗时不含排队、图片准备或发送；失败数也明确使用同一近期样本。

当前任务与本次启动最近 100 条任务保存在内存，每条最多 32 个步骤；模型请求与发送回执持久化。列表接口优先选取运行中、等待中与最近结束的任务，再限制为最多 60 条状态摘要，避免高负载时把正在处理的用户任务截掉。步骤随 `/api/runtime/operations/{id}` 按需读取，避免 5 秒轮询重复搬运过程明细。该详情可关联查看上下文准备、图片、模型调用和发送结果。重启后近期任务步骤消失，已保存的调用与发送记录仍可查看。首页展示最近 20 次模型请求和前 30 条任务，不自动重发不确定结果。

运行账本每天清理一次：超过 90 天的模型调用、主动发送尝试、终态发送回执与决策留痕会被删除；`pending` 意图保留供人工核查。仍被决策留痕引用的回执不删，聊天时间线可以继续把 Bot 消息接回详情。观察窗口快照超过 7 天只清空快照正文，决策结论保留到 90 天。删除前将调用次数、失败/未知用量计数和已知 Token 汇入 `AiUsageArchives` 的单行累计汇总，并与删除共用事务。无聊天历史的旧版回复也保留用量汇总，已有历史回复不重复归档。首页累计数合并汇总与现存明细，按日期查询仍只统计该范围的明细。清理失败可回滚，重复执行不会重复累计；不改动聊天记录、群记忆或业务配置。

普通回复遇到模型执行超时，会在宿主仍运行时使用独立有限的发送期限给出超时提示；停机取消不额外发送。

## 7. 共用群记忆

普通 @ 回复新增 `AiConfigs.GroupMemoryInjectionEnabled` 全局开关，默认开启；主动发言保留自己的全局开关。两者都尊重群级禁止注入设置，私聊不读取群记忆。主动工作流只注入一次，普通回复的记忆纳入最终输入预算。摘要仍由管理员维护，不自动生成或更新。

## 8. 前端按需加载

Element Plus 改为组件及样式按需引入，路由继续懒加载；服务式消息框样式显式引入，中文语言配置通过 ConfigProvider 提供。构建插件选择支持项目现有 Node 版本线的 28.x。

同一构建模式下，入口主 JavaScript 从约 1,121,703 字节降为约 383,950 字节，减少约 66%。这是入口文件未做传输压缩时的大小，不代表整个首页的所有资源，也不等同于实际加载耗时的降幅。统计图表仍只在进入统计页时加载。

## 9. 聊天记录与决策详情

聊天页把已保存消息与择机评估合并成一条按时间排序的会话时间线，分页用 `消息ID:留痕ID` 快照冻结，翻旧页时新到的消息不会挤动已看过的页。查找在 SQLite 内完成，`%`、`_` 与反斜杠按字面处理；群、来源、发送者与决策理由可以组合过滤。Bot 消息与决策留痕只按直接 `MessageId` 或发送回执的 `PlatformMessageId` 精确关联，不靠文本和时间猜。

切换群或来源时先请求轻量首屏：只取最新 50 条并多取一条判断是否还有更早记录，不在返回正文前扫描全量总数。页脚先显示“总数统计中”，独立的计数请求沿用同一 `消息ID:留痕ID` 快照在后台补齐；在总数返回前仍可直接进入“更早”，旧分页接口和完整页码保持原协议。群名、Bot 回执关联和页内消息/留痕都只按当前页涉及的 ID 读取，取消请求会透传到剩余 SQL。实测 4 个各 3 万条消息、各 4000 条留痕的热群，48 次循环切换 p50 9ms、p95 12ms、max 15ms；10 万消息 + 1 万留痕的原有基线约 52/11/47/100ms。

普通群消息在入库并推送 SignalR 后直接按同一时间线规则并入当前最新页，最多保留 50 条并按 `kind:id` 去重，不再为每条消息整页重查。Bot 回复与评估留痕需要精确接回，因此合并为一次 1.5 秒后的静默校准；校准运行时不 abort 正在完成的请求，期间到达的事件只记一个待刷新标记，完成后再安排下一轮。查看旧页、搜索结果或向上翻阅时仍只显示新记录提醒，普通消息合并和重连补齐都不会挤动当前内容。浏览器实测切到 3 万条热群首屏约 84ms，页内实时消息约 109ms 出现在底部且没有触发时间线重查，从旧页返回最新约 85ms。

一旦跳过实时记录，或正在等待 Bot/重连校准，后续普通消息不能单独推进分页快照；恢复跟随后收到推送时先合并校准，再继续增量更新。校准响应到达时若已上翻、打开详情或暂停实时更新，则保留当前正文与新记录提醒；翻旧页也不会清除提醒。暂停后恢复实时更新会主动补齐，即使复用现有连接、没有新的重连事件也能恢复完整时间线。页面状态回归直接编译实际 Vue setup，使用合成数据、可控时钟和延迟请求覆盖上述交叉场景。

决策详情读取评估时保存的观察窗口。窗口最多 50 条、每条 2000 字、总正文 20000 字，按 UTF-8 原文保存，截断不会切开 emoji 的代理对。快照只在群设置为「围观并记录全部消息」且这次评估真的进入模型时写入；只 @ 的群以及评估前被冷却/日限/关闭等门禁挡下的记录不保存群友原话。隐私门槛上线前写入的旧快照不再从详情接口返回，7 天后由保留策略清空。详情里的附图张数是实际随请求附上的张数，不是窗口里出现过图片的总数。

新留痕单独保存是否已进入模型评估，模型返回后被发送门禁拦截也计入「今日决策」；旧留痕不补造阶段标记，优先采用已有模型/用量证据并保留旧版兼容口径。诊断完整性从 v2 起确认，旧 v1 的默认零值继续显示「未记录」，已有的正数与已联网标记仍可查看。回执归档与清理只认可非空平台消息 ID 的关联，避免空引用阻止删除并造成累计用量重复归档。

## 10. 分群择机参数与预设

择机参数采用“全局默认 + 群级稀疏覆盖”。接话节奏与观察时段分成两张卡片，其余判定和通道参数默认收起。下拉菜单、时段选择、切换器与弹窗统一使用 Element Plus；数值框不显示原生上下加减箭头。每项明确标注来源，恢复跟随时删除覆盖值，因此后续全局修改可以自动影响仍在继承的群。切群保留各群草稿，离开页面时统一提示未保存修改。

预设可保存全部可分群参数，或仅保存本群自定义项。应用前展示参数对照，只载入当前范围的草稿，保存设置后生效；预设修改或删除不会改变已经复制到群的参数。全局总开关、全部群日限与账号分钟频控不进入预设，也不能被群级覆盖。原有群记忆使用权限仍独立生效。

旧库通过幂等补列增加 `GroupConfigs.ProactiveOverridesJson`，未设置的项继续继承；预设存入独立的 `ProactivePresets` 表。调度仅读取有待评估窗口的群，领取任务时重新核对群参数；模型调用使用本群预算与发言倾向，发送前再核对最新静默时段、参与开关与共享配额。原有群管理保存流程保留这些覆盖值。

## 11. AI 设置分区与配置预设

AI 设置按「模型连接」「回复风格」「上下文与记忆」「联网与检索」四块组织，字段统一使用 `AiSettingField` 的标签、提示和参数说明入口。配置预设保存整套可写配置快照，主模型 Key 单独存放并按「包含密钥/沿用当前密钥」处理；外搜 Key 不进入预设，只在服务商与地址一致时于应用阶段沿用当前值。预设最多 50 个，支持新建、覆盖、复制、改名和删除。

保存配置时先校验表单，再提交 `PUT /config/ai`；服务端接受后立即把本次提交值作为脏状态基线，再 best-effort 回读最新配置。回读失败只提示“已保存，但读取失败”，不会把已保存的配置误报成未保存。外搜服务商切换时前端清空旧 Key 与地址，后端也只允许同服务商的空值/打码值沿用原 Key，避免把旧服务商的密钥发给新服务商。

外搜数值只在「独立搜索服务」启用时校验；关闭通道后遗留的非法值不会阻塞整个配置保存。加载时按界面精度与范围收敛温度、Token 预算和外搜数值，并提示用户确认，避免“显示 0.8、实际提交 0.75”的错位。

## 兼容与验证

数据库只通过现有幂等升级增加调用表、累计汇总表、关联列、记忆开关和索引，升级过程不删除业务数据。运行期保留策略清理超过 90 天的运行账本与决策留痕，并清空超过 7 天的观察窗口快照；回退程序时保留这些附加结构。旧程序不读取累计汇总，重新升级后恢复相应显示。新配置在核心、数据库实体、API 与面板中统一使用 24576 的输入默认预算，已有配置保持原值。

```powershell
dotnet build Mutter.sln
dotnet run --project tools/ProactiveCheck -- --logic-only
cd web
npm test
npm run build
# 浏览器回归需 Node.js 20 及以上；首次运行先安装 Chromium。
npx playwright install chromium
npm run test:ui
```

运行时回归共 41 组，覆盖实际请求归属、未知用量、格式重试、手动探测、5000 条带长正文的记录汇总、缓存命中、图片并发/淘汰/取消、独立记忆开关、保存事务回滚、过程关联和运行账本保留策略。另含 10 万消息下的时间线去重规模、4 个各 3 万消息热群的切换/轻量首屏/延迟总数一致性、观察窗口快照的群级隐私与门禁边界、旧库升级幂等、空回执归档幂等、评估后门禁与旧诊断兼容、跨连接事件交接、满队列取消后的恢复序号、真实宿主停机、高负载任务展示和累计归档回滚/幂等检查。另含群级覆盖继承、旧库升级、预设重名/删除与范围边界、群级窗口领取及发送前策略变化检查、外搜 Key 服务商归属与旧打码兼容。前端逻辑测试覆盖旧请求晚到、页面取消、实时消息去重与页内上限、快照推进、过滤条件、决策标题、停用群提示及容量关系，已接入 CI。

本地另用 Edge 无界面浏览器与合成 API/SignalR 数据检查全部管理页面、编辑提醒、合并保存、实时筛选、断线恢复、日志去重、组件解析与首页布局。验证不读取部署数据库，不访问真实 QQ 或付费模型。

弹窗尺寸回归已随前端 CI 执行：在真实构建页面中创建群级草稿并触发离开确认，验证 1920/1440/390/320px、深浅两种主题下 MessageBox 的 420px 上限与手机 16px 留边，同时确认预设 Dialog 保留其独立的 600px 宽度。“继续编辑”保留草稿，“放弃修改”才能完成导航。
